Implement one phase at a time. After each phase: run migrations, seeders and the full test suite and fix all failures; update `docs/requirements-traceability.md`; summarise what was built, how to run it and any decisions needed; commit; then STOP and wait for the owner's approval. Commit after each completed task with a clear message. Never mark a requirement done without a passing test.

## Phase 1 — Foundation (task list approved in the Phase 0 plan)
1. Dependencies: `composer require laravel/reverb laravel/horizon spatie/laravel-permission spatie/laravel-medialibrary spatie/laravel-backup maatwebsite/excel`; `php artisan install:broadcasting --reverb`; `php artisan horizon:install`; publish permission/medialibrary/backup configs and migrations; `npm i laravel-echo pusher-js @zxing/browser` and `npm i -D vite-plugin-pwa`; `.env` → Redis cache/queue/session; `config/app.php` timezone `Asia/Muscat`, locale `ar`, fallback `en`; `config/database.php` MySQL connection documented with timezone `+00:00`.
2. Enums: all enums in `docs/db-schema.md` (`php artisan make:enum`), `OrderStatus::transitions()`, `label(locale)`; arch tests (`App\Enums` string-backed; no `DB::raw` in `app/Actions`).
3. Migrations: all 33 tables in the documented order, `utcTimestamps()` Blueprint macro; `migrate:fresh --seed` green on SQLite and MySQL 8.4; GitHub Actions matrix job with a MySQL 8.4 service running the `concurrency` group.
4. Models: relations, `casts()`, `#[Fillable]`, `HasUuids` on orders/payments/devices, `LocationProduct extends Pivot`, `HasBilingualName`, `BelongsToLocation`, `@property` docblocks; factories with named states (`Location::factory()->active()->withSchedule()`, `Product::factory()->withVariants()->withAddonGroup()`, `Order::factory()->pendingPayment()/paid()/ready()`, `Device::factory()->kiosk()`, ...).
5. Seeders: `RolesAndPermissionsSeeder`, `OrderNumberSequenceSeeder` (`R`, 1001), `SettingsSeeder`, `MessageTemplateSeeder`, owner user, `DemoSeeder` with location "Rofliv – Sohar University" (schedule, slot settings, staff), bilingual sample menu (categories, products with placeholder images, variants, add-on groups with min/max, a custom-text product), per-location stock, one kiosk device.
6. Roles & scoping: global roles owner, admin, manager, staff, kitchen + `location_user.role` override; permission list; `Gate::before` for owner/admin; `EnsureLocationAccess`, `EnsureUserIsActive` (+ `Fortify::authenticateUsing` rejecting inactive users); policies for Location, Category, Product, AddonGroup, Coupon, User, Device, Order (effective role + location; cross-location 404).
7. Admin shell: `AdminLayout` (sidebar: Dashboard, Orders, Locations, Menu → Categories/Products/Add-on groups, Inventory, Coupons, Users, Devices, Settings), shared props (auth user, roles, permissions, locations, locale, translations, flash toast), locale switcher, RTL, `lang/ar.json` + `lang/en.json`, `useTrans()`.
8. Admin CRUD (Inertia pages + FormRequests + policies + actions): Locations (all §10 fields: bilingual name/venue/description/address, slug, event dates, `ordering_opens_on`, schedule editor + exceptions, slot length, min lead, default capacity, status, staff assignment with per-location role, auto-print flags, ASAP toggle, staff-confirmation toggle, payment TTL override, QR download PNG/SVG for `/l/{slug}`), Categories, Products (bilingual, images via medialibrary, variants, add-on group attachment, custom text flag + max length, sticker fields, soft delete, enable/disable), Add-on groups & add-ons (min/max), per-location menu/stock/price page (`is_listed`, `is_available`, price override, stock quantity, one-click restock/re-enable, Sold-Out indicator), Users & roles (create, role + locations, reset password, deactivate), Devices (pairing code generation, revoke).

10. Tests (Pest, feature-first): auth redirect, role matrix per admin endpoint (dataset over roles), cross-location 404, validation per FormRequest, happy paths asserting persisted state, policy matrix, QR download content types, phone rule dataset, money formatting, seeder smoke test, enum arch test, migration smoke on MySQL in CI.

## Phase 2 — Online ordering & payments
Slot generation and capacity (`GeneratePickupSlots`, `SlotAvailability`, next-slot suggestion, per-slot capacity edits), `CartPricer` (variants, add-ons min/max, custom text, coupons, clamps), coupon admin + concurrency-safe reservation/confirmation/release, `PlaceOrder` reservation transaction, order numbers at confirmation, status machine + history, `PaymentGateway` contract + `FakeGateway` (local checkout page with Succeed / Fail / Timeout posting a signed webhook), `StartPaymentAttempt`, webhook endpoint + `payment_events` idempotency + redrive, `ReconcilePendingPayments`, `ExpireUnpaidOrders` (+ grace, per-order jobs), late/duplicate payment handling with idempotent refunds, Attention list in admin, customer website flow (§2 steps 1–11: location picker within event dates, cached menu with Sold Out badges, product customisation, slot picker, name/phone, coupon, review/confirm, pay, confirmation with order QR), `/o/{uuid}` status page with Reverb + polling fallback, Apple Pay well-known route, rate limiters, tests (including the MySQL concurrency group).

## Phase 3 — Booth operations

## Phase 4 — Notifications, dashboard, hardening
`WhatsAppNotifier` contract + `LogWhatsAppNotifier`, `message_templates` admin (AR/EN, enable/disable, placeholders `{order_number}`, `{customer_name}`, `{location}`, `{pickup_time}`, provider template names), queued `SendWhatsAppMessage` with retries and `notification_logs` delivery status, dashboard (today's sales and orders, AOV, sales by location and by event/venue, best sellers, current/upcoming/ready orders, payment-method and source breakdowns, event/location comparison, date-range and location filters, live updates) + Excel/CSV exports (`data_exports`, queued), spatie backup (daily DB + local storage to an off-site disk, retention, failure notifications, media via bucket versioning), rate-limiting review, performance pass (query counts, indexes, caching), tests; final traceability update.
